# Guichê v1.6.0 — Auditoria da Fase 07

## Fase

Follow-up DX — composição do scheduler durável existente.

## Baseline

Fase 06 concluída:

```text
b750c02be6bc6c104837a24657fd656a32c07116
feat(v1.6): add session lifecycle and ttl
```

## Objetivo

Reduzir a complexidade de composição do follow-up sem reimplementar:

- Scheduler;
- FollowUpScheduler;
- ScheduledEventRunner;
- stale;
- dedupe;
- lease/fencing;
- recovery;
- indeterminate.

## Decisão arquitetural

O `Guiche` continua sem responsabilidade de scheduling.

O `GuicheBuilder` não recebe follow-up.

Foi adicionada somente a facade:

```text
Asmpkg\Guiche\Conversation\FollowUpRuntime
```

Classificação:

```text
experimental
```

## DX

Configuração sugerida:

```dotenv
GUICHE_FOLLOWUP_ENABLED=true
GUICHE_FOLLOWUP_AFTER=7200
```

Factory:

```php
FollowUpRuntime::fromDirectories(...)
```

Operações:

```text
schedule()
runDue()
find()
cancel()
enabled()
defaultDelaySeconds()
```

## Garantias preservadas

- nova mensagem muda sequence e torna timer antigo stale;
- mudança de requiredState torna timer stale;
- mesma sequence continua deduplicada;
- handler válido executa uma vez;
- falha incerta vira indeterminate;
- indeterminate não recebe retry automático;
- disabled não agenda nem claim;
- eventos persistidos continuam canceláveis quando disabled.

## Compatibilidade

- Scheduler não foi modificado;
- FollowUpScheduler não foi modificado;
- ScheduledEventRunner não foi modificado;
- Guiche não foi modificado;
- GuicheBuilder não foi modificado;
- API pública estável permanece com o mesmo baseline;
- freeze Experimental foi revisado explicitamente de 11 para 12 símbolos.
