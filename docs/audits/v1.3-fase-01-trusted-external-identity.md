# Guichê v1.3.0 — Fase 01 — Trusted External Identity

## Baseline

- `main`: `422961e973be702f5ed1b50f64db098ca81f9fb1`
- versão pública anterior: `v1.2.0`
- branch: `feature/v1.3.0-contexto-externo-confiavel`

## Objetivo

Expor no entrypoint público `Guiche` a operação de vincular uma identidade externa confiável a uma sessão sem obrigar o consumidor a conhecer `ExecutionContextSeeder`.

Fluxo alvo:

```text
Aplicação externa
→ Guiche::bindIdentity()
→ execution_context.identity write-once
→ TenantResolver (quando configurado)
→ execution_context.tenant_id
→ ToolExecutionContext
→ Tools contextuais
```

## Decisões

1. `bindIdentity()` recebe somente `sessionId` + mapa de identity.
2. Conteúdo de mensagem, state e argumentos produzidos pela IA não entram no binding.
3. O mecanismo write-once existente continua sendo a autoridade (`ExecutionContextSeeder`).
4. Quando existe `TenantResolver`, o binding resolve o tenant imediatamente pelo `TenantResolutionService`.
5. O resolver continua recebendo somente a identity confiável.
6. Campos extras retornados pelo resolver não são promovidos automaticamente a `execution_context`.
7. Repetir a mesma identity é idempotente.
8. Tentar trocar identity em sessão já vinculada falha fechado.
9. Tenant já resolvido não é resolvido novamente.
10. Nenhuma assinatura pública existente foi quebrada.

## Testes desta fase

- persistência da identity externa;
- idempotência com ordem de chaves diferente;
- bloqueio de identity swap;
- resolução de tenant a partir apenas da identity;
- não promoção de campos extras do resolver;
- não repetição do resolver após tenant persistido;
- isolamento entre duas sessões/tenants;
- regressão de `ExecutionContextSeeder` e `TenantResolutionService`;
- quality gate completo.

## Roadmap v1.3.0

1. **Fase 01 — Public API / bindIdentity** — esta fase.
2. **Fase 02 — Trusted identity pipeline** — normalização, contratos de erro e fluxo identity→tenant→Tool.
3. **Fase 03 — Security + observability** — eventos auditáveis, falhas, write-once/idempotência e proteção contra dados não confiáveis.
4. **Fase 04 — External adapters / Chatwoot** — integração de referência e exemplo de host externo.
5. **Fase 05 — Concurrency + regression + DX** — concorrência, isolamento, instalação externa e ergonomia.
6. **Fase 06 — Docs + API freeze + release** — README, migração, changelog, acceptance, tag `v1.3.0`.

## Critério de encerramento

A Fase 01 só fecha se a nova API estiver coberta por PHPUnit, o baseline público for atualizado explicitamente como adição compatível de v1.x e `composer84 check` permanecer verde.
