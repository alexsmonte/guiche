# Guichê v1.4.0 — Fase 02 — Runtime Prompt Resolution

## Objetivo

Introduzir resolução dinâmica de prompt em runtime sem quebrar a API
estática existente e sem permitir que conteúdo controlado pelo usuário
decida qual prompt operacional será carregado.

## Decisões arquiteturais

1. `GuicheBuilder::withInstructions()` permanece compatível.
2. `GuicheBuilder::withPromptResolver()` aceita:
   - `PromptResolverInterface`;
   - `Closure`.
3. Closures são adaptadas por `CallbackPromptResolver`.
4. O prompt dinâmico é resolvido uma única vez por `handle()`.
5. A resolução ocorre antes de:
   - `StateManager::onUserMessage()`;
   - persistência da mensagem do usuário;
   - primeira chamada ao provider de IA.
6. O mesmo prompt resolvido é reutilizado em todas as rodadas de Tool
   da mesma interação.
7. `PromptContext` é construído somente a partir de:
   - `sessionId`;
   - `execution_context` persistido;
   - tenant resolvido pela fronteira confiável, quando configurado.
8. Mensagem atual, histórico de mensagens, `state`, output da IA e
   argumentos livres de Tool não participam da seleção do prompt.
9. Quando existe `TenantResolverInterface`, a resolução dinâmica exige
   identidade confiável previamente vinculada e falha fechada se ela
   estiver ausente.
10. Prompt dinâmico vazio falha fechado antes de chamar a IA.
11. Instruction Fragments e instruções estáticas continuam sendo
    compostos ao prompt final.
12. O `Cli\PromptResolver` legado permanece interno e sem promoção para
    API pública nesta fase.

## Compatibilidade

Sem `withPromptResolver()`, o caminho legado permanece:

`withInstructions()` → `Guiche` → `AiProviderInterface`

Com resolver dinâmico:

`sessionId`
→ `execution_context`
→ `TenantResolutionService` quando aplicável
→ `PromptContext`
→ `PromptResolverInterface`
→ prompt do turno
→ instruções estáticas/fragments
→ provider de IA

## Segurança

A seleção do prompt fica fora da superfície controlada pelo modelo ou
pela mensagem do usuário. O runtime mantém a separação entre:

- contexto operacional confiável;
- estado conversacional;
- conteúdo da conversa;
- argumentos de Tool.

## Aceite da fase

- callback/Closure funcional;
- resolver por interface funcional;
- tenant disponível em `PromptContext`;
- resolução ocorre uma vez por turno;
- prompt permanece estável entre rodadas de Tool;
- prompt vazio falha fechado;
- tenant prompt sem identidade confiável falha fechado;
- `withInstructions()` legado continua funcional;
- API pública atualizada explicitamente;
- quality gate completo verde.
