# Guichê v1.1.0 — Fase 02

## Session Execution Context + Identity Binding

Eixo arquitetural:

```text
SESSION → CONTEXTO → TENANT → TOOL
```

## Objetivo

Vincular `execution_context` confiável a uma `sessionId`, sem alterar
`ContextStoreInterface` e sem permitir troca posterior de identidade
ou tenant.

## Decisões

- `ContextStoreInterface` permanece intacto.
- Contextos novos normalizam `execution_context => []`.
- Contextos legados sem o campo continuam compatíveis.
- `ExecutionContextSeeder` recebe dados de fronteira confiável.
- `identity` é obrigatório no Seeder.
- Cada chave de `execution_context` é write-once.
- Chaves novas podem ser acrescentadas posteriormente.
- Chaves já persistidas não podem mudar.
- Chaves antigas omitidas por saves legados são preservadas.
- `tenant_id`, quando existir, não pode ser trocado.
- O `ContextStore` padrão protege o binding dentro do lock exclusivo
  já usado para escrita por sessão.
- Payload persistido com `execution_context` inválido falha fechado.

## Evolução permitida

```text
identity
   ↓
tenant_id
   ↓
outros valores resolvidos
```

## Trocas proibidas

```text
identity A → identity B
tenant A   → tenant B
```

## Isolamento

```text
session A → identity A → tenant A
session B → identity B → tenant B
```

## Compatibilidade preservada

- ToolInterface;
- ContextStoreInterface;
- Tools legadas;
- state;
- messages;
- tool_history;
- usage;
- schema_version atual;
- persistência atômica;
- locking existente.

## Fora de escopo

A resolução real:

```text
identity → TenantResolver → tenant
```

fica para a Fase 03.

A execução de `ContextAwareToolInterface` pelo runtime fica para a fase
de Contextual Runtime.
