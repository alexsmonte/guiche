# Guichê v1.4.0 — Fase 05 — Multi-tenant + Security + Framework Integration

## Objetivo

Validar a resolução dinâmica de prompt sobre o contexto multi-tenant
confiável já existente, comprovar isolamento sob concorrência e
documentar integração com aplicações/frameworks sem acoplar o Core.

## Fluxo de confiança

```text
SESSION
→ bindIdentity()
→ execution_context.identity
→ TenantResolver
→ execution_context.tenant_id
→ PromptContext
→ PromptResolver
→ prompt
```

## Regras de segurança validadas

1. Mensagem do usuário não escolhe tenant.
2. `state` conversacional não escolhe tenant.
3. Argumentos de Tool não escolhem tenant.
4. `PromptContext` recebe somente `execution_context`.
5. Identity é write-once por sessão.
6. Tenant é derivado de identity confiável.
7. Rebinding conflitante falha fechado.
8. Prompt A não pode aparecer em sessão B.
9. Concorrência entre sessões A/B não pode causar cross-tenant leak.
10. Observabilidade não deve expor identity, tenant ou prompt brutos.

## Concorrência

O acceptance cria múltiplos processos em paralelo compartilhando o
mesmo ContextStore, com workers alternando entre duas sessões e dois
tenants.

Cada worker deve receber exclusivamente o prompt do tenant vinculado à
sua sessão.

## Frameworks

Integrações documentadas:

- CakePHP;
- Laravel;
- Symfony;
- PHP puro.

Nenhum namespace de framework é adicionado a `src/`.

As dependências entram pelo `guiche.php` Composition Root.

## Compatibilidade

Nenhuma API pública nova é adicionada nesta fase.

São exercitadas APIs já existentes:

- `Guiche::bindIdentity()`;
- `TenantResolverInterface`;
- `PromptResolverInterface`;
- `PromptContext`;
- `GuicheBuilder`;
- Composition Root da Fase 03.

## Aceite

- duas sessões usam prompts de tenants distintos;
- tentativa de forge por mensagem é ignorada;
- tentativa de forge por state é ignorada;
- rebinding conflitante falha fechado;
- prompt original continua após tentativa de troca;
- observabilidade não contém valores brutos sensíveis;
- concorrência multiprocesso não cruza prompts;
- Composition Root aceita dependências de container externo;
- Core continua sem dependência CakePHP/Laravel/Symfony;
- API freeze permanece compatível;
- `composer84 check` completo verde.
