# Guichê v1.1.0 — Fase 06 — Isolation + Security + Regression

## Objetivo

Provar que o contexto dinâmico multi-tenant não permite mistura de
identidade, tenant ou efeitos entre sessões.

## Matriz validada

### A → A / B → B

Duas sessões distintas, usando a mesma instância de Tool, resolvem e
executam somente nos respectivos tenants.

```text
session-a → identity clinic-a → tenant 101
session-b → identity clinic-b → tenant 202
```

### Identity write-once

Depois que `execution_context.identity` é vinculada a uma sessão, outra
identity não pode substituir a original.

### Tenant write-once

Depois que `tenant_id` é resolvido e persistido, tentativa de trocar o
tenant falha fechada.

### Argumento de tenant forjado

Há duas camadas de proteção:

1. Tools clínicas não expõem `empresa_id` no schema e o Hard Gate rejeita
   o campo adicional antes do banco;
2. em chamadas PHP diretas a `executeWithContext()`, as Tools clínicas
   sobrescrevem qualquer `empresa_id` recebido com o tenant do
   `ToolExecutionContext`.

### ContextAware sem sessão

Uma Tool contextual sem `sessionId` falha com
`context_session_required` antes de executar.

### WRITE sem tenant

Mesmo com sessão e identity válidas, uma WRITE contextual sem tenant
resolvido falha com `tenant_context_required` antes de side effect.

### Resolver com falha

Falha de resolução produz `tenant_context_unavailable`, não executa a
Tool e não inclui a mensagem bruta da exceção no envelope de bloqueio.

### Legacy Tools

Tools que implementam apenas `ToolInterface`:

- continuam aceitando execução sem sessão;
- continuam passando por `ToolRegistry::execute()`;
- não acionam `TenantResolver`.

## Concorrência

O acceptance `bin/test-v11-multitenant-isolation.php` dispara oito
processos concorrentes tentando vincular duas identities diferentes à
mesma sessão.

Critérios:

- ao menos uma identity vence;
- o JSON final permanece íntegro;
- a sessão termina com uma única identity;
- a resolução do tenant corresponde à identity vencedora;
- identity swap posterior é bloqueado;
- tenant swap posterior é bloqueado.

## Resultado arquitetural

A fronteira fica:

```text
SESSION
  ↓
IDENTITY IMUTÁVEL
  ↓
TENANT IMUTÁVEL
  ↓
TOOL CONTEXTUAL
```

A IA permanece fora da decisão de tenant.
