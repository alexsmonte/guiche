# Guichê v0.5.1 — Fase 01 / Baseline + Contracts

## Baseline

- versão anterior: `v0.5.0 — Persistence & Observability`
- baseline: `97b2b00cb8e6a5e1e9d6c1948c181edb55749b07`
- branch: `feature/v0.5.1-conversation-runtime`

## Fronteira arquitetural

```text
ConversationRuntime = quando processar
Guiche              = como processar/raciocinar o turno
```

A v0.5.1 não deve deslocar para dentro de `Guiche::handle()` responsabilidades de buffer, debounce, scheduler, lease, follow-up ou stale-event protection.

## Ordem fechada de implementação

```text
Conversation Store
→ Incoming Events
→ Sequence
→ Buffer
→ Turn
→ Debounce
→ Scheduler
→ Claim/Lease
→ Stale Protection
→ Follow-up
```

## Escopo desta fase

Somente:

1. `ConversationStoreInterface`;
2. `ClockInterface`;
3. teste dos contratos;
4. auditoria de fronteira;
5. regressão completa da v0.5.

## ConversationStoreInterface

Contrato inicial mínimo:

```text
load
mutate
delete
```

`mutate()` representa o ponto atômico por `conversation_key`: implementação futura deve manter a seção crítica durante leitura, callback e persistência.

Não adicionar nesta fase métodos específicos de IncomingEvent, Buffer, Turn, Scheduler ou Follow-up.

## ClockInterface

Toda lógica temporal futura deverá depender do relógio injetável para permitir testes determinísticos de debounce, lease, recovery e follow-up sem `sleep()`.

## Fora do escopo

Não implementar nesta fase:

- IncomingEvent;
- deduplicação;
- sequence real;
- Message Buffer;
- ConversationTurn;
- Quiet Window;
- Max Turn Window;
- Scheduler;
- Claim/Lease;
- Follow-up;
- stale detection;
- workers.
