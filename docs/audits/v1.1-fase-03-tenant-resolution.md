# Guichê v1.1.0 — Fase 03

## Tenant Resolution

Eixo arquitetural:

```text
SESSION → CONTEXTO → TENANT → TOOL
```

Nesta fase o trecho implementado é:

```text
sessionId
   ↓
ContextStore[sessionId]
   ↓
execution_context.identity
   ↓
TenantResolverInterface
   ↓
tenant_id
   ↓
ExecutionContextSeeder
   ↓
execution_context.tenant_id
```

## Regras

### A identidade é a única entrada da resolução

O resolver recebe exclusivamente:

```php
$executionContext['identity']
```

Não recebe:

- state;
- messages;
- argumentos da Tool;
- argumentos produzidos pela IA;
- conteúdo textual da conversa.

### Tenant já vinculado não é resolvido novamente

Se `execution_context.tenant_id` já existe e é válido,
`TenantResolutionService` reutiliza o binding persistido.

Isso preserva a estabilidade:

```text
session A → tenant A
```

durante toda a sessão.

### Resultado persistido mínimo

Resolvers podem consultar sistemas ricos, mas o Core promove
automaticamente somente:

```text
tenant_id
```

Campos extras retornados por banco, API ou repository são ignorados pelo
pipeline padrão e não entram automaticamente no contexto da sessão.

### Fail closed

Falha explicitamente quando:

- identity não existe;
- identity é inválida;
- resolver não encontra tenant;
- tenant_id é vazio/inválido;
- SELECT/procedure retorna mais de uma linha;
- campo obrigatório de identity está ausente;
- resposta de API não contém o caminho configurado.

## Resolvers públicos

### SqlTenantResolver

Serve tanto SELECT quanto stored procedure/CALL.

Exemplo SELECT:

```php
new SqlTenantResolver(
    $db,
    'SELECT id_empresa FROM whatsapps WHERE phone_number_id = :phone',
    ['phone' => 'phone_number_id'],
    'id_empresa'
);
```

Exemplo procedure:

```php
new SqlTenantResolver(
    $db,
    'CALL resolver_tenant(:external_key)',
    ['external_key' => 'account.external_key']
);
```

### HttpTenantResolver

Usa `HttpClientInterface` e aceita caminhos aninhados para resposta:

```php
new HttpTenantResolver(
    $http,
    'https://example.test/tenant/resolve',
    ['phone_number_id' => 'phone_number_id'],
    'data.tenant_id'
);
```

### CallbackTenantResolver

Adapter genérico para repository, service ou integração customizada:

```php
new CallbackTenantResolver(
    fn (array $identity): array => [
        'tenant_id' => $repository->resolve($identity),
    ]
);
```

## Isolamento esperado

```text
session A
  identity A
  resolver
  tenant A

session B
  identity B
  resolver
  tenant B
```

Nenhum resultado de A pode contaminar B.

## Compatibilidade

Permanecem intactos:

- ToolInterface;
- ContextStoreInterface;
- TenantResolverInterface da Fase 01;
- ExecutionContextSeeder da Fase 02;
- Safety Layer;
- Tools legadas;
- Guiche runtime.

## Fora de escopo

O `Guiche` ainda não executa `ContextAwareToolInterface`.

A conexão:

```text
tenant_id → ToolExecutionContext → Tool
```

será feita na Fase 04 — Contextual Runtime.
