## Acceptance obrigatório

O release exige sucesso de:

1. contratos do Conversation Runtime;
2. Incoming Events + deduplicação + sequence;
3. Message Buffer + ConversationTurn;
4. Quiet Window + Max Turn Window;
5. Durable Scheduler;
6. Claim + Lease + Fencing Token + Reclaim;
7. Stale Protection;
8. Follow-up;
9. Recovery;
10. estado `indeterminate`;
11. regressão completa v0.5;
12. Safety Layer v0.4;
13. Plugin Contracts v0.3;
14. Core Extraction v0.2;
15. integração clínica preservada;
16. `git diff --check`.

## Invariantes finais

### Turn

```text
mensagens
  ↓
quiet window 40s
  OU
max window 120s
  ↓
um ConversationTurn
  ↓
uma chamada ao Guiche
```

### Scheduler

```text
pending
  ↓
claim
  ↓
claimed + lease_token
  ↓
completed
```

Lease expirado antes da execução pode ser reclaimed.

Fencing token antigo não pode concluir após reclaim.

### Follow-up

Default inicial:

```text
300 segundos
```

Configurável.

### Stale protection

```text
sequence_snapshot=N
conversation.sequence muda
worker revalida
→ stale
→ handler não executa
```

Precondições de state também são revalidadas.

### Resultado externo incerto

```text
handler iniciou
resultado externo ficou incerto
→ indeterminate
→ terminal
→ sem retry automático
```

Somente a classe da falha é persistida.

## Fronteiras

- `ConversationRuntime` decide quando processar;
- `Guiche` decide como processar o turno;
- scheduler não é responsabilidade de `Guiche`;
- Core permanece neutro de domínio;
- regras clínicas não entram no Conversation Runtime.
