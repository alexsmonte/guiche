### 5. Regras de migração

- O diretório `src/` deve terminar sem implementação de domínio clínico.
- O exemplo clínico pode depender dos contratos públicos do Guichê; o Core não pode depender do exemplo.
- As cinco Tools permanecem registradas via Plugin API.
- O StateManager clínico permanece plugável.
- Presenters permanecem registrados pelo plugin.
- Configuração e prompt clínicos deixam de ser configuração do Core/pacote raiz.
- Nenhum segredo, endpoint privado obrigatório, CPF real, paciente real ou dado de produção entra no exemplo.
- Fake Mode deve executar o fluxo sem MySQL, Clinsoft, Internet ou OpenAI real.
- O WRITE de criação de agendamento deve continuar protegido por confirmação, idempotência e `forbids_state`.
- Imediatamente antes do WRITE deve existir revalidação do slot escolhido.
- Agendamento já existente deve impedir criação duplicada e conduzir o fluxo de forma explícita.
- Result Projection continua expondo somente os campos autorizados à IA.
- A migração só pode remover caminhos antigos depois de todos os testes apontarem para a nova localização.
