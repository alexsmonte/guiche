# GUICHÊ v1.0.0 — Fase 03 — Consumidor real/representativo

## Objetivo

Resolver o P1-002 validando a release publicada `v0.9.0` em um projeto externo ao repositório do Guichê.

## Instalação testada

- Package: `asmpkg/guiche`
- Versão exigida: `v0.9.0`
- SHA publicado: `21cce7b82f8cb303e8b72891a8cc857939f666c3`
- Origem: `https://github.com/alexsmonte/guiche.git`
- Instalação: Composer VCS remoto
- Path repository: **NÃO**
- Symlink para checkout local: **NÃO**
- Uso do vendor do projeto Guichê: **NÃO**

## Cenário representativo

O consumidor implementou fora do pacote:

- `ToolInterface`;
- `PluginInterface`;
- `AiProviderInterface`;
- composição via `GuicheBuilder`;
- persistência usando o `ContextStore` público.

A Tool externa foi registrada como WRITE com:

`requires_state: state.release_approved = true`.

## Comportamentos comprovados

1. WRITE sem o estado obrigatório: **BLOQUEADO**.
2. Side effect do WRITE bloqueado: **0 execuções**.
3. WRITE após estado válido: **AUTORIZADO**.
4. Side effect autorizado: **1 execução**.
5. Repetição do mesmo WRITE na mesma sessão: **REPLAY IDEMPOTENTE**.
6. Side effect após replay: **continua em 1 execução**.
7. Provider externo completa o ciclo conversacional: **PASS**.

## Evidência do programa

```text
PASS: WRITE sem estado obrigatório é bloqueado pelo hard execution gate
PASS: WRITE bloqueado não executa side effect
PASS: WRITE com estado obrigatório válido é autorizado
PASS: WRITE autorizado executa side effect exatamente uma vez
PASS: repetição do mesmo WRITE é tratada como replay idempotente
PASS: replay não repete o side effect
PASS: provider externo conclui a conversa após Tool output
CONSUMER_ACCEPTANCE=PASS
```

## Resultado

**PASS**

A `v0.9.0` funciona como dependência real de uma aplicação externa representativa, sem alterações no Core e sem dependência do checkout de desenvolvimento.

P1-002 — feedback/validação de consumidor real ou representativo: **RESOLVED**.

Nenhuma incompatibilidade de DX/API bloqueante foi encontrada neste cenário.
