# Guichê v1.3.0 — Fase 03 — Security + Observability

## Baseline

- branch: `feature/v1.3.0-contexto-externo-confiavel`
- parent esperado: `beb6b401f4fa9678b4683c0b04ebb5cfa141fca3`
- Fase 01: API `bindIdentity()`
- Fase 02: Trusted Identity Pipeline endurecido

## Objetivo

Tornar o binding de identidade externa confiável auditável sem transformar
observabilidade em um novo canal de vazamento.

## Eventos

O fluxo passa a produzir eventos best-effort:

```text
trusted_identity_binding_started
trusted_identity_bound
trusted_identity_binding_failed
trusted_tenant_resolution_succeeded
trusted_tenant_resolution_failed
```

## Dados permitidos nos eventos

- `session_key` em SHA-256, fornecido pelo `RuntimeEventFactory`;
- `identity_fingerprint`;
- `tenant_fingerprint`;
- flags booleanas de estado;
- reason code estável;
- classe da exception.

## Dados proibidos nos eventos

- `sessionId` em claro;
- `identity` em claro;
- `tenant_id` em claro;
- `execution_context`;
- mensagem bruta de exception;
- payload do resolver.

O `RuntimeEventFactory` passa a eliminar explicitamente as chaves
`identity`, `tenant_id` e `execution_context`, inclusive quando aparecem
aninhadas.

## Fail-closed

A instrumentação não muda a autoridade do pipeline.

- `ExecutionContextSeeder` continua sendo o enforcement de write-once;
- tentativa de troca continua falhando;
- falha do TenantResolver continua falhando;
- falha do sink de observabilidade não interfere no binding;
- nenhum evento concede ou altera tenant.

## Fronteira com a IA

`execution_context` não é promovido para as instruções da IA.

O teste da fase comprova que valores exclusivos de:

```text
identity.account_id
identity.inbox_id
identity.conversation_id
tenant_id
```

não aparecem nas instruções entregues ao `AiProviderInterface`.

## Compatibilidade

Nenhuma assinatura pública é alterada.

O baseline da API v1 deve permanecer exatamente o mesmo da Fase 02.

## Critérios de aceite

1. binding bem-sucedido produz trilha auditável;
2. rebinding idempotente é distinguível;
3. tentativa de troca é auditada e bloqueada;
4. falha do resolver é auditada sem mensagem sensível;
5. falha do sink é best-effort;
6. raw identity/tenant/context nunca entram no sink;
7. contexto confiável não entra no prompt da IA;
8. API freeze preservado;
9. `composer84 check` verde;
10. commit local apenas.
